① Dockerfile — Every Line Explained docker build

The Dockerfile defines your container image. Layer ordering matters — put stable layers first to maximize cache reuse.

Dockerfile 
# Base image — Python 3.11 minimal
FROM python:3.11-slim

# Set working directory inside container
WORKDIR /app

# Copy requirements FIRST — enables layer caching
COPY requirements.txt .

# Install dependencies (--no-cache-dir keeps image small)
RUN pip install --no-cache-dir -r requirements.txt

# Copy app source code (after pip — code changes don't bust pip cache)
COPY ./app ./app

# Tell Docker the app listens on port 8000
EXPOSE 8000

# Start FastAPI with uvicorn
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
⚡

Layer caching tip: COPY requirements.txt before COPY ./app. If code changes but requirements don't, pip install is reused from cache. Rebuild: 5 min → 5 sec.

③ GitHub Actions Workflow CI/CD

The workflow triggers on push to main, runs tests, then builds and pushes the Docker image to ECR.

.github/workflows/deploy.yml 
name: CI/CD Pipeline

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install -r requirements.txt
      - run: echo "tests pass"

  build-and-push:
    needs: test  # only runs if tests pass
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v2
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ap-southeast-2
      - uses: aws-actions/amazon-ecr-login@v1
        id: login-ecr
      - run: |
          docker build -t $ECR/$REPO:$TAG .
          docker push $ECR/$REPO:$TAG
        env:
          ECR: ${{ steps.login-ecr.outputs.registry }}
          REPO: sebi-policy
          TAG: ${{ github.sha }}
💡

Each image is tagged with github.sha — the commit hash. This makes every push traceable and lets you roll back to any previous version in ECR.

④ AWS IAM — Two Users to Create IAM

You need two separate IAM users — one for your daily work, one for the CI/CD bot. Never use root credentials.

rahul-admin

  • IAM → Users → Create user
  • Name: rahul-admin
  • Enable console access + set password
  • Policy: AdministratorAccess
  • Use this for daily AWS work — never root

github-actions-user

  • IAM → Users → Create user
  • Name: github-actions-user
  • No console access needed
  • Policy: AmazonEC2ContainerRegistryFullAccess
  • Policy: AmazonECS_FullAccess
  • Security credentials → Create access key
  • Use case: Application outside AWS
  • Download CSV immediately — secret shown once!
⚠️

Download the CSV for github-actions-user immediately. The secret access key is only shown once and cannot be retrieved again.

⑦ AWS ECS — Cluster → Task → Service ECS · Fargate

⑧ Env Vars in ECS Task Definition config

In production, secrets are injected directly into the ECS task definition — not via a .env file.

ECS Task Definition → Container → Environment Variables 
aws_access_key_id      → your rahul-admin key
aws_secret_access_key  → your rahul-admin secret
region_name            → ap-southeast-2
BEDROCK_CHAT_MODEL     → amazon.titan-text-express-v1
BEDROCK_EMBEDDING_MODEL → amazon.titan-embed-text-v2:0
⚠️

For production workloads, consider using AWS Secrets Manager or SSM Parameter Store instead of plain env vars in the task definition.
