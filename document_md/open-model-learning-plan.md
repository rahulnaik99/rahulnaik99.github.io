# Open-Model Inference, Evaluation & Deployment: Learning Steps

| Step | Title | Description | Skills I learn | Difficulty | Importance | Link |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | LLM inference basics with vLLM | Take the DeepLearning.AI course, then rebuild its lab: compress a Qwen model, serve it with vLLM, benchmark it. | Prefill vs decode, KV cache, continuous batching, PagedAttention, prefix caching | Medium | High | [Course](https://www.deeplearning.ai/short-courses/fast-and-efficient-llm-inference-with-vllm/) |
| 2 | Run vLLM yourself | Serve one open model on a rented GPU (or a small model locally) and call it through the OpenAI-compatible API from Python. | vLLM setup, OpenAI-compatible API, GPU memory sizing | Medium | High | [vLLM docs](https://docs.vllm.ai) |
| 3 | Quantization trade-offs | Serve the same model at FP16, FP8 and AWQ 4-bit. Compare memory, tokens/sec and accuracy on your own prompts. | Quantization, LLM Compressor, accuracy vs speed trade-offs | Medium | High | [LLM Compressor](https://github.com/vllm-project/llm-compressor) |
| 4 | Load benchmarking | Test at 1, 8 and 32 concurrent users. Record TTFT, p95 latency and throughput in a results table and chart. | Benchmarking, TTFT, p95 latency, throughput under load | Medium | High | [GuideLLM](https://github.com/vllm-project/guidellm) |
| 5 | Managed open-model APIs | Try Together, Fireworks or DeepInfra for the same model. Compare price, latency and reliability against your own server. | Provider comparison, per-token pricing, BYO weights | Easy | High | [Together AI](https://www.together.ai) |
| 6 | Gateway and routing | Put one endpoint in front of your vLLM, a hosted open model and a closed model, with fallback rules. | LiteLLM, routing, retries, fallbacks, provider abstraction | Medium | High | [LiteLLM docs](https://docs.litellm.ai) |
| 7 | Tracing and cost tracking | Trace every request with latency, tokens, cost and model used. Build a cost and p95 dashboard per model. | Observability, Langfuse or Phoenix, cost tracking | Medium | High | [Langfuse](https://langfuse.com) |
| 8 | Eval fundamentals for agents | Take the Arize course. Add tracing to an agent and choose code, LLM-judge or human evaluators per component. | Eval design, code evaluators, LLM-as-judge, trajectory evals | Easy | High | [Course](https://www.deeplearning.ai/alpha/short-courses/evaluating-ai-agents) |
| 9 | Build a golden eval set | Write 100 to 150 labelled cases from your own domain (RAG questions, tool-call tasks) with a documented rubric. | Dataset design, labelling, rubric writing | Medium | High | [Promptfoo](https://www.promptfoo.dev) |
| 10 | RAG evaluation | Score your RAG pipeline on retrieval recall and precision, faithfulness and answer relevance. Record a baseline. | RAG metrics, Ragas or DeepEval, baselines | Medium | High | [Ragas](https://docs.ragas.io) |
| 11 | Trustworthy LLM judges | Label 50 cases yourself, compare to the judge, report agreement (Cohen's kappa), and refine the rubric. | Judge calibration, precision, recall, Cohen's kappa | Hard | High | [Course](https://www.deeplearning.ai/short-courses/evaluating-and-improving-agentic-applications/) |
| 12 | Regression testing in CI | Run all candidate models through one command and fail the build when the score drops below baseline. | Regression tests, CI for evals, model comparison tables | Medium | High | [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) |
| 13 | Containers and Kubernetes basics | Containerize the vLLM server and deploy it to a local cluster with Helm. | Docker with GPUs, Kubernetes, Helm, vLLM Production Stack | Hard | Medium | [vLLM Production Stack](https://github.com/vllm-project/production-stack) |
| 14 | Autoscaling and distributed serving | Add autoscaling on request rate or queue depth, test a zero-downtime model swap, and read about llm-d. | KEDA, autoscaling, rolling updates, llm-d, disaggregated serving | Hard | Medium | [llm-d](https://llm-d.ai) |
| 15 | Self-host vs managed cost model | Build a calculator showing the monthly token volume where self-hosting beats the managed API, using your measured throughput. | Cost modelling, GPU utilisation, break-even analysis | Medium | High | [DeepInfra provider comparison](https://deepinfra.com/blog/best-open-source-llm-api-providers) |
| 16 | Optional: fine-tuning and LLMOps | Learn supervised fine-tuning pipelines and LoRA adapters; link to your existing finetune project. | SFT, LoRA/QLoRA, versioning data and models | Medium | Medium | [LLMOps course](https://deeplearning.ai/short-courses/llmops) |
| 17 | Portfolio write-up | Publish the repo, README, architecture diagram and a blog post comparing open and closed models on cost, latency and quality. | Technical writing, reproducibility, honest trade-off analysis | Medium | High | [Udemy LLMOps Bootcamp (optional extra)](https://www.udemy.com/course/ultimate-llmops-bootcamp/) |
