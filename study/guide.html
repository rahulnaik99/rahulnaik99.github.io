Sparse Retrieval — BM25

Fine-Tuning

LoRA & QLoRA

Why Fine-Tune
  • Domain-specific language — mortgage terms, medical, legalMUST
  • Output style control — underwriter narrative formatMUST
  • Cost reduction — fine-tuned 8B > GPT-4o quality at $0 per callMUST
  • Latency — local model, no API round tripGOOD
  • Privacy — no data sent to OpenAIGOOD
Full Fine-Tuning vs LoRA
  • Full fine-tuning — updates all weights, needs 80GB+ GPU, impracticalMUST
  • LoRA — freeze base weights, add small A×B adapter matricesMUST
  • Output = W·x + scale × A·B·x — tiny delta on frozen weightsMUST
  • Only 0.1% of params trained — fits on consumer GPUMUST
QLoRA Specifics
  • Q = quantize base model to 4-bit — 8B model goes from 16GB to 4GBMUST
  • LoRA adapters trained in 16-bit on top of 4-bit baseMUST
  • NF4 quantization — normal float 4, optimal for normally distributed weightsGOOD
  • Double quantization — quantize the quantization constants tooNICE
Key Hyperparameters
  • r (rank) — size of A,B matrices. r=16 sweet spot for 8BMUST
  • lora_alpha — scale = alpha/r. Keep equal to rMUST
  • target_modules — q_proj, k_proj, v_proj, o_proj, gate/up/down_projMUST
  • lora_dropout — 0 is optimal with QLoRAGOOD
  • learning_rate — 2e-4 standard for LoRAGOOD

Transformer Architecture

Attention Mechanism

Self-Attention
  • Q, K, V — Query, Key, Value projections from inputMUST
  • Attention formula — softmax(QK^T / √d_k) × VMUST
  • √d_k scaling — prevents dot products from getting too largeMUST
  • Attention score — how much each token attends to every otherMUST
  • Causal masking — future tokens masked in decoderMUST
Multi-Head Attention
  • Why multiple heads — each head learns different relationshipsMUST
  • h heads × d_head dimensions = d_model totalMUST
  • Heads concatenated then projected back to d_modelGOOD
  • GQA — Grouped Query Attention, fewer KV heads, faster inferenceGOOD
  • MQA — Multi-Query Attention, single KV head sharedNICE
Positional Encoding
  • Why needed — attention has no sense of token orderMUST
  • Sinusoidal — original Transformer, fixed frequenciesGOOD
  • Learned positional embeddings — BERT approachGOOD
  • RoPE — Rotary Positional Embedding, used in LlamaMUST
  • RoPE extends context — rotate Q,K vectors by position angleGOOD
  • ALiBi — linear bias on attention scoresNICE
KV Cache
  • Stores K,V matrices from previous tokens — avoid recomputeMUST
  • Critical for fast autoregressive generationMUST
  • Memory grows linearly with context lengthMUST
  • PagedAttention — vLLM, manages KV cache like OS memory pagesGOOD
Attention Variants
  • Flash Attention — IO-aware, fused CUDA kernel, much fasterMUST
  • Flash Attention 2 — better parallelism, ~2x fasterGOOD
  • Sliding window attention — Mistral, each token attends to local windowGOOD
  • Sparse attention — attend to subset of tokensNICE
